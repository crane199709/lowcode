# 热敏标签以整张位图下发 ZPL/TSPL

ZPL 与 TSPL 的原生文本指令走单字节字符集，中文标签要么依赖打印机内置字库（机型绑定），要么走厂商私有代码页（型号绑定）。icube 的做法是用 `charset` 配文本指令，实际只能打 ASCII 与数字。本仓库改为：服务端把整张标签按 DSL 渲染成 HTML，再栅格化为 1-bit 位图，ZPL 用 `^GFA`、TSPL 用 `BITMAP` 下发。这样"预览即打印"严格成立，不依赖打印机字体、字符集与机型；代价是丢失打印机端的字体替换与矢量缩放能力，且指令体积变大（300dpi、50×30mm 的标签约 590×350 点，压缩后几 KB，实际链路无压力）。XML 文本指令模式留作二期可选开关，不作为默认。

## Considered Options

- **文本指令 + 打印机内置中文字库**：指令最小，但每换一批打印机就要重新适配字体与码页，且预览与打印必然不一致。
- **文本指令 + 仅支持 ASCII 字段**：实现最简单，但中文标签（姓名、项目名、机构名）是主场景，等于砍掉主要用途。
- **位图（采用）**：一次渲染两处复用，无字体依赖；代价是打印机端不可再排版。

## Consequences

- 标签的边界处理（元素越界、文字裁切、条码区域）必须在服务端确定，不能指望打印机裁剪。
- 位图分辨率与 DPI 绑定：同一模板在 203dpi 与 300dpi 下生成的指令不同，模板里不能出现亚像素依赖。
- 标签上的文字在打印后不可检索、不可被打印机重新排版；需要"可编辑文本层"的场合只能走 PDF。
